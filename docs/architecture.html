Coding-agent OpenTelemetry Collector — clients, flows, and code structure

Custom Collector distribution (otelcol-coding-agents, OCB-pinned) that normalizes coding-agent telemetry into a canonical trace per user turn while exporting raw vendor telemetry in parallel. Source of truth: builder-config.yaml, collector-config.yaml, docs/design.md.

End-to-end flow through the Collector

Code and class structure

One component type with two edges. The module layout mirrors opentelemetry-collector-contrib: public Collector surface at the module root, provider logic in internal packages so schemas stay out of the public API.

connector/codingagentconnector component root

Public Collector surface (own Go module, built into the distribution via OCB)

  • NewFactory — factory.go; registers the logs and traces edges (connector.NewFactory), default config, stability from generated metadata.
  • Config = codex.Config — config.go alias so mdatagen docs/validation stay on the component type. The same knobs bound both stateful edges.
  • logsRouter — logs.go; fans each logs batch to the codex and cursor claimers; Start/Shutdown fan out because both edges own sweep loops and drain state. Each record lands in at most one edge; unclaimed records stay out of canonical output.
  • tracesRouter — traces.go; fans each traces batch to the four stateless normalizers (claude, genai, opencode, pi). Claims are disjoint: genai yields groups to Claude and OpenCode first, and the remaining predicates match disjoint scope/name sets, so a group is emitted at most once.
  • internal/metadata — mdatagen-generated status and TelemetryBuilder (self-metrics wiring).

internal/codex stateful

Reconstructs one canonical trace per user turn from structured Codex logs

  • codingAgentConnector — connector.go; ConsumeLogs entrypoint, mutex-guarded turns map[string]*turnState, background sweepLoop ticker; Shutdown drains all active turns with finish reason “shutdown”.
  • turnState — event slice, seen-fingerprint set, first/last/lastSeen timestamps, completeSeen/completionAt, promptSeen, truncated flag.
  • parseEvent (event.go) — claims records whose event.name starts codex. and carries conversation.id; strips prompt/arguments/output before retention.
  • fingerprint() — sha256 over name, timestamp, attributes; dedupes at-least-once redelivery inside a live turn so token usage is not double-counted.
  • buildTrace (trace.go) — deterministic IDs: traceID = sha256(conversationID + prompt timestamp). One chat span per turn-completion response.completed, execute_tool spans per tool_result joined by call_id, remaining events as root span events. Re-emitting a finalized turn reproduces identical IDs.
  • Bounds and finalization — max_active_turns LRU eviction, max_events_per_turn truncation flag; reasons: completed, superseded, timeout, shutdown, evicted.
  • telemetry (metrics.go) — coding_agent.active_turns gauge (provider=codex) plus emitted/dropped/truncated counters.

internal/cursor stateful

Correlates native Cursor logs into activity-burst traces (Enterprise beta wire)

  • cursorConnector — connector.go; same lifecycle shape as codex: bursts map, sweep loop, flushAll on Shutdown.
  • burstState — event slice plus seen set keyed exactly on cursor.event.id; same bounds as turnState.
  • ParseRecord (event.go) — claims the cursor.telemetry scope when a conversation id is present; declines codex-named records.
  • buildTrace (trace.go) — root invoke_agent cursor spanning the burst; one point chat span per api_request (no durations invented); cache token rollups; api_error / api_correction join chat spans via cursor.usage_event.id; unmatched records become root events. Attribute policy is an allowlist, so canonical output stays content-free.
  • Finalization — quiet (normal close), timeout measured from burst start (error status), shutdown, evicted. Clock semantics differ from codex (inactivity-based) because Cursor has no completion event on the wire.

internal/claude · genai · opencode · pi stateless

Traces-to-traces normalization; copies pdata, preserves all IDs and hierarchy

  • claude.New (normalizer.go) — detected by span-name prefix; renames only interaction / llm_request / tool span types; everything else keeps native names; maps session.id to gen_ai.conversation.id; dangling parents stay intact so backends can reassemble across batches.
  • opencode normalizer — exact-scope claim (opencode); filter-and-rebuild: ai.streamText/doStream/toolCall spans become one invoke_agent opencode per model step with chat children; internal instrumentation spans and all content attributes dropped.
  • pi normalizer — scope or telemetry.sdk.name prefix claim; reparents orphaned chat/tool spans onto invoke_agent pi roots within the batch; renames chat/execute_tool; exporter-local Langfuse baggage and raw usage blobs never reach canonical output.
  • genai normalizer — claims resource groups by scope-name allowlist prefixes (openai_v2, util.genai, strands.telemetry, github.copilot), after the Claude-first and OpenCode checks; runs content stripping on every claimed span, matched scope or not.
  • Name tables — rewrites only when the subject attribute is present: chat {model}, invoke_agent {agent}, execute_tool {tool}. Copilot's agent subject is producer-chosen (copilot-cli / copilotcli variants).
  • Attribute work — legacy token-key mapping (prompt/completion → input/output), gen_ai.system fallback for provider, provenance attributes, removal of content-bearing attributes and events.
  • Copy-on-write — reports MutatesData:false and copies before modifying so Collector fan-out stays safe.

distribution + deployment files packaging

What turns the component into a running Collector

  • builder-config.yaml — pins OCB v0.159.0; otlp receiver, batch + resource processors, otlp/awss3/file exporters, file_storage + healthcheck extensions, this connector.
  • Dockerfile — two-stage build; OCB generates the dist main package, ships a single binary plus bundled config; EXPOSE 4317 / 4318 / 13133.
  • collector-config.yaml — e2e shape: three pipelines (logs/vendor, traces/native, traces/canonical) with file exporters.
  • compose.e2e-*.yaml stacks — eight opt-in live harness stacks (codex, claude, openai-adhoc, strands, opencode, pi, copilot, openhands) sharing the collector via include; each defines only its own agent service, parameterized by env.
  • examples/otelcol-s3.yaml — production reference: one S3 prefix per stream, persistent sending queues on local file_storage with fsync, bounded queue size and database size.
  • State contract — correlation state is memory-only; exporter queues persist completed batches but not active turns. See docs/multi-instance-ha.md for the N-instance analysis.
